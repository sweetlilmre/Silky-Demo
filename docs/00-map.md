# The load image of SILKY.EXE

The measurement target is `bin/SILKY.EXE`, 10,704 bytes on disk: a 576-byte MZ header, then a 10,128-byte load image that this project bases at paragraph `0x1000`. It is the first Asphyxia production, written in 1993 for Silky's eighteenth birthday, and `bin/README.1ST` says it is the first demo in which they used chain-4 — "the consequence of this is that the program should be the same with turbo on or off".

The compiler is **Turbo Pascal 6.0**, named by the runtime's own banner at `11a6`: `Portions Copyright (c) 1983,90 Borland`.

## Where the segment boundaries came from

Not from a linker map. `src/` is empty, so nothing has been built and there is no map to read. The boundaries are the paragraphs named by the MZ relocation table — 136 fixups naming five distinct targets, `112f` `113c` `1144` `11a6` `1247`, plus `1000` as the load base. Ghidra derives its `CODE_n` blocks from the same fixups, so the two agreeing is one measurement read twice rather than two measurements agreeing.

What *is* independent is the arithmetic. Each segment's extent is the next one's base, the chain closes at paragraph `1279`, and `(0x1279 - 0x1000) * 16 = 10128` — the load image size computed from the MZ header's page count by a different route. Two routes, one answer.

**The blind spot: a unit no fixup names.** A base only appears above if something refers to it across a segment boundary. A unit never entered from outside its own segment is invisible to this method, and would sit inside its neighbour's extent with nothing reporting it. Until there is a linker map, a "segment" here is a paragraph something far-refers to, and nothing stronger.

## What the tail is not

Ghidra draws a block it calls `CODE_5` at `1247:0000..031f`, because four fixups name paragraph `1247`. Those four are references *to* the data group — a `MOV AX,DGROUP` loading `DS` — rather than code inside it. `survey.py` settles it: zero far returns in 800 bytes, and one printable string running the length of the segment.

> `HAPPY BIRTHDAY SILKY, HERE'S WISHING U A GR8 18TH!!! ALL THE BEST FROM ASPHYXIA!!!` … `GREETS GO TO :- SCHMUCK, EARWAX, NOBODY, SPLIT, JAVELIN AND ALL THE OTHERS.` … `A S P H Y X I A   R U L Z !!!!!!`

That is the scrolltext, and it is data. The segment walk therefore ends at `1247` rather than `1279`, and `end_at` and `dgroup_at` are both that paragraph — equal here because the segment list includes the runtime.

## Not part of the reconstruction

`bin/BARS.INC` is **original Turbo Pascal source** that shipped with the demo — 4,691 bytes of `{$I}` include, CRLF, pure ASCII, holding `Procedure DeltaPal; assembler;` with real inline assembler and a `Drawit` that calls `PutPixel`. It is a build input and evidence, not something to reconstruct.
